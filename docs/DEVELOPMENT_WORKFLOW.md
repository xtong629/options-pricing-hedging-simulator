# 开发、评审与发布

每阶段从刚同步的 origin/main 建立[计划](MASTER_PLAN.md)所列分支。一次 PR 交付一个可独立复核的阶段；扩展按提案拆分。保留真实作者、日期和有意义的 Conventional Commits，例如 docs(design)、feat(pricing)、test(ledger)、fix(risk)。提交前检查 diff，排除凭据、虚拟环境及大型中间数据。

PR 正文说明业务问题、变更范围、公开接口和单位、验证命令与实际结果、数值公差、已知局限及复现配置。文档阶段检查交叉引用、公式和阶段依赖。Phase 1 建立 pyproject.toml、src 安装流程和 GitHub Actions，在 Python 3.11 上执行安装、ruff check、ruff format --check 和 pytest；后续阶段扩充相应检查，Phase 5 增加支持版本矩阵、构建 wheel 并在干净环境验证 CLI。大型研究手动执行并记录来源。

## 合并检查

- 数学评审逐项核对符号、年化尺度、边界和独立基准；统计评审核对独立样本单位、种子与区间。
- 对冲评审重放交易、融资、股息、到期和首尾费用，检查决策输入的时间戳。
- 工程评审核对类型、输入兼容性、确定性回归、性能预算、API 变更说明、文档与输出一致性。
- 作者推送分支并创建 PR。发生冲突时同步 main 后重验。所有适用检查通过且用户明确批准后才可合并；建议启用 main 分支保护。下一阶段从合并后的 main 开始。

## 发布条件

Phase 5 候选提交须可独立安装、运行快速实验并重建完整研究表图。发布说明列出模型范围、复现命令、基准平台、已知限制和 API 变化。经审查批准后在验收提交上标记 v1.0.0（Core Pricing, Risk & Hedging Analytics）；此后按兼容性区分补丁、次版本和主版本。
